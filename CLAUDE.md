# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Jackson jr is a compact alternative to `jackson-databind`: a subset of databinding (JDK types, Beans, Records) built directly on the `jackson-core` streaming API. Small jar size and low startup overhead are the reason it exists, so `jr-objects` must depend only on `jackson-core`, and new functionality should be weighed against its size cost. Optional functionality belongs in an extension module.

## Branches: 2.x and 3.x differ substantially

This checkout holds both major versions, so check the current branch before assuming package names or Java level.

| | 2.x line | 3.x line |
|---|---|---|
| Maven group / Java package | `com.fasterxml.jackson.jr` | `tools.jackson.jr` |
| Streaming dependency | `com.fasterxml.jackson.core` | `tools.jackson.core` |
| Java level (CI JDKs) | 8 (8, 11, 17, 21) | 17 (17, 21, 23) |
| Exceptions on the `JSON` API | checked `IOException` | unchecked `JacksonException` |
| Module descriptors | generated by Moditect | `module-info.java` in the source tree, including tests |
| Record tests | separate `jr-record-test` module | in `jr-objects` tests |
| Release notes | `release-notes/VERSION-2.x` | `release-notes/VERSION` |

Changes flow by forward-merging: `2.x` is merged into `3.x`, and older release branches into newer ones (`2.22` -> `2.x`, `3.2` -> `3.x`). A fix needed in both lines usually starts on the oldest applicable branch.

**After switching between 2.x and 3.x, build with `clean`.** `target/generated-sources` is not cleared automatically, so a stale `PackageVersion.java` from the other line causes "cannot find symbol" compile errors.

## Commands

Use the Maven wrapper. CI runs the first command below.

```sh
./mvnw -B -q -ff -ntp verify                     # full build and tests, as in CI
./mvnw clean install                             # build and install locally

./mvnw test -pl jr-objects                       # tests for one module
./mvnw test -pl jr-objects -Dtest=ReadMapTest    # one test class
./mvnw test -pl jr-objects -Dtest='ReadMapTest#testName'   # one test method

# Module that depends on others: -am builds them from the reactor too.
# The extra flag stops upstream modules failing because they lack the named test.
./mvnw test -pl jr-stree -am -Dtest=CreateNodesTest -Dsurefire.failIfNoSpecifiedTests=false
```

There is no separate lint or format step.

## Modules

- `jr-objects`: the core: `JSON` API, readers, writers, composers, type resolution.
- `jr-stree`: minimal immutable `TreeCodec` implementation (`Jrs*` nodes).
- `jr-annotation-support`: subset of Jackson annotations, as an extension.
- `jr-extension-javatime`: subset of `java.time` types, as an extension.
- `jr-retrofit2`: Retrofit 2 converters.
- `jr-all`: uber-jar of `jr-objects` and `jr-stree`, with `jackson-core` relocated (shaded) to `...jr.private_`.
- `jr-record-test` (2.x only), `jr-groovy-test`: test-only modules. `jr-record-test` compiles `src/test-jdk17` only when built on JDK 17 or later, so Record tests silently don't run on older JDKs.

## Architecture (`jr-objects`)

**`JSON` is the immutable, thread-safe entry point.** `JSON.std` is the default instance; `with(...)`/`without(...)` and `JSON.builder()` produce new instances. It owns the `JsonFactory`, features bitmask, `TreeCodec`, and "root" `JSONReader`, `JSONWriter`, `ValueReaderLocator` and `ValueWriterLocator`.

**Each operation uses per-operation instances.** Every read or write calls `perOperationInstance(...)` on the root reader/writer, which does the same on its locator. Roots hold shared configuration and caches, and per-operation copies hold the parser/generator and transient state. Custom `JSONReader`/`JSONWriter` subclasses must override `perOperationInstance`.

**Reading and writing are structured differently:**

- **Reading** is object-based. `ValueReaderLocator` resolves a type (using `TypeResolver` from the `type` package) to a `ValueReader`: `BeanReader`, `MapReader`, `CollectionReader`, `ArrayReader`, `EnumReader`, `SimpleValueReader`, or `AnyReader` for untyped content. Resolved readers are cached in a bounded cache, with handling for recursive types.
- **Writing** is switch-based for speed. `ValueWriterLocator` maps a class to an `int` type code (`SER_*` in `ValueLocatorBase`, shared with the reader side), and `JSONWriter` dispatches on it. There are parallel switches in `_writeValue` and `writeField`, so a new built-in type has to be added to both. Negative type codes are outside the switch and mean a Bean or an explicit `ValueWriter`.

**Bean introspection:** `BeanPropertyIntrospector` builds a `POJODefinition` (properties and constructors), which the locators turn into `BeanReader`/`BeanWriter`. `RecordsHelpers` detects Records reflectively, so the code compiles on Java 8.

**Extension points** live in `ob.api` and are the way to add behavior without touching the core:

- `JacksonJrExtension` is registered through `JSON.builder().register(...)` and receives an `ExtensionContext`.
- `ReaderWriterProvider` supplies custom `ValueReader`/`ValueWriter`s. Providers are chained, and each is registered at either the highest or lowest precedence.
- `ReaderWriterModifier` adjusts `POJODefinition`s and handlers. `jr-annotation-support` is built on this: it applies annotations by rewriting the definition, while `jr-objects` itself knows nothing about annotations.
- `MapBuilder` and `CollectionBuilder` control the container types constructed when reading.

**Composers** (`ob.comp`, entered through `JSON.composeString()` etc.) are a separate fluent write path directly over `JsonGenerator`, with no POJO model involved.

## Build and test conventions

- `PackageVersion.java` is generated from `PackageVersion.java.in` during the build: edit the template, not the generated file.
- `javac.debuglevel` is set to `source` to minimize jar size, dropping line numbers and local variable names from compiled classes. Expect stack traces without line numbers.
- Tests use JUnit 5 and generally extend the module's test base (`TestBase` in `jr-objects`). Regression tests are named after the issue number, e.g. `ReadNestedContainers223Test`.
- Tests for known, unfixed bugs go in the `tofix` test package, annotated `@JacksonTestFailureExpected`. They pass while the bug exists and fail once it is fixed, at which point the test should move out of `tofix` and lose the annotation.
- User-visible changes get an entry in the release notes file for the branch (see the table above), under the unreleased version. Contributors are listed in `release-notes/CREDITS-2.x`.
